# RCA: почему Autopilot остановился перед T-V2-08

**Дата:** 2026-09-05  
**Предмет:** T-V2-08 (Settings: таблица проектов + global save) не начата; пауза после T-V2-07  
**Тип:** расследование процесса, код `app/` не менялся  
**Чат:** [47436cb2](47436cb2-65af-44c4-b6bd-c70b5ad466ca)

---

## Root cause

Остановку принял **координатор родительского чата**, не пользователь, не PO spec и не режим Autopilot `semi`. Координатор резал каждый прогон Task-агента по границе волны («Wave 1 + начало Wave 2 если успеешь»; «T-V2-05, 06, дальше по возможности T-V2-07») и после отчёта сам просил пользователя написать `/autopilot продолжи`. Мандат пользователя был один: «утверждаю spec/tasks» + `/autopilot продолжи` на весь план T-V2-01…22, без «остановись после wave 1».

## Почему план T-V2-01…22 не доехал в одной сессии

Три независимых механизма сложились:

1. **Нарезка промптов координатором.** Один `/autopilot продолжи` пользователя стал двумя (потом многими) Task-прогонами с потолком «эта волна». Агент 83e107c4 взял ещё T-V2-07 («по возможности»), T-V2-08 в список не входил: это уже Settings UI, не API.
2. **Ложный human-gate.** После каждого прогона координатор писал «напиши `/autopilot продолжи`». Пользователь в этот момент занимался `.env`, semver, AWS, дашбордом. Следующая волна кода не стартовала, пока его явно не спросили «почему пауза».
3. **Не тот `/autopilot` в Cursor.** Команда пользователя подставляет PR-skill (merge-ready CI), BUILD-skill из `~/.agents/skills/autopilot` как непрерывный полёт не шёл. Оркестрация: родитель + Task, без фазы 5 «wave is not a barrier».

`semi` здесь ни при чём: в semi координатор **сам начинает** после плана и не ждёт approve на каждую волну. Ждать «продолжи» нужно только если прогон оборвался или пользователь сказал «стоп».

## Соответствие манифесту vs мандат пользователя

| Источник | Ожидание |
| --- | --- |
| Пользователь | Утвердил spec/tasks, `/autopilot продолжи` на сборку; деплой AWS отдельно, **после** кода. |
| Manifest «Порядок» | Код T-V2-01…22, затем acceptance, затем T-V2-DEPLOY. |
| Skill `semi` | Спросить на развилке продукта; волны лететь дальше; «продолжи» = resume. |
| Фактическое поведение | Пауза на границе волны + просьба новой команды пользователя. |

Фактическое поведение **не соответствует** ни манифесту, ни skill, ни мандату пользователя. Соответствует только **самоограничению координатора** в тексте Task.

Поздний ответ «пауза потому что semi» зафиксировал неверную причину и усилил тот же антипаттерн.

## Что исправить в процессе

1. Промпт исполнителю: «все pending T-V2-* по графу deps, пока не упрёшься в T-V2-DEPLOY или в явный стоп пользователя». Не писать «Wave N если успеешь» и не требовать «следующий `/autopilot продолжи`» в «Вернуть».
2. После done тикета сразу стартовать следующий с закрытыми deps. Граница волны: параллельность, не human-gate.
3. «`/autopilot продолжи`» в чат пользователю только если сессия оборвалась, пользователь сказал «стоп», или есть настоящая развилка (OAuth, секреты, deploy).
4. Не списывать паузу на `semi`: default режима не равен «жди команду после каждой волны».
5. Развести Cursor-команду `/autopilot` (сейчас PR merge-ready) и BUILD-skill; иначе координатор снова будет имитировать полёт через урезанные Task.

Проверка: пользователь не писал «остановись после wave 1». Следующий код: T-V2-08 без повторного «можно ли продолжать».
