## Вердикт

Приложение **выглядит готовым и не является таковым**. Каркас (статусная машина, адаптеры, восстановление воркера, тесты) сделан аккуратно, но три центральные функции продукта **имитируются**, причём имитация записывается в БД и показывается пользователю как реальный результат. Контур входа пускает любой аккаунт Google; разделения данных между пользователями нет.

Формальный гейт «`npm test` 160/160» проходит, потому что не проверяет типы, безопасность и живые интеграции.

**Итог:** качественный прототип, выданный за v0.2.0 в проде. До цели Pulse («заменяет ручные заметки на настоящем созвоне») не хватает трёх реализаций, а не полировки.

## P0. Блокеры

### P0-01. Google OAuth пускает кого угодно

**Файл:** `app/src/server/routes/auth.ts` (строки ~186-207)

- Callback создаёт нового пользователя для любого `profile.sub` из Google.
- Нет allowlist email, нет `email_verified`, нет ограничения домена.
- `state` генерируется в `/google/start`, не сохраняется и не сверяется в callback (нет защиты от login CSRF).
- Снаружи не эксплуатируется только из-за `127.0.0.1` + SSH-туннель (nginx), не из-за кода.

**Противоречие Pulse:** решение 2026-09-05 «закрыть доступ посторонним».

### P0-02. Трекеры фиктивны, фикция пишется в БД

**Файлы:**

- `app/src/adapters/tracker/types.ts` (~39-53): `createTasks` не вызывает API, возвращает `created` при `connected`.
- `app/src/server/routes/integrations.ts` (~11-21): GET «Подключить» пишет токен `"stub"`.
- `dispatchTrackerActionItems` вызывает `markActionItemsSentToAsana` для всех id.

**Сценарий потери данных:** пользователь видит «создано», в ClickUp пусто, в БД `tracker_state = created`, повторная отправка невозможна.

### P0-03. Meet и Телемост выдают чужую «расшифровку»

**Файл:** `app/src/adapters/platform/join.ts` (~33-43)

- `MeetAdapter`, `TelemostAdapter` → `{ mode: "stub", audioPath: null }`.
- Конвейер → `stubTranscribe` → `fixtures/demo-meeting.json` сохраняется как транскрипт, резюме, задачи, статус `ready`.
- UI: подпись «заглушка realtime», текст расшифровки неотличим от реального.

**Противоречие Pulse:** Zoom, Meet, Телемост обязательны (решение 2026-09-03).

### P0-04. Нет проверок владельца данных

**Файл:** `app/src/server/middleware/session.ts`

- `c.set("userId", userId)` нигде не читается в обработчиках.
- Встречи, проекты, настройки, аудио глобальны для любой сессии.

### P0-05. Миграция портит данные при каждом перезапуске

**Файл:** `app/src/db/schema.ts` (~24-36)

- `UPDATE action_items SET tracker_type = CASE asana_state ...` выполняется при каждом `migrate()`, без `columnExists` guard.
- **Зонд:** `tracker_type='clickup'` после рестарта становится `asana`, `tracker_external_id` сохраняется.
- Нет `user_version` / однократных миграций.

### P0-06. Гейт качества не ловит ошибки

- `tsc --noEmit`: 18 ошибок; prod: `routes/projects.ts`, `routes/search.ts`, `worker/pipeline.ts`.
- `vitest run` не проверяет типы.
- Нет линтера; стиль `zoom-bot.ts` расходится с остальным кодом.

## Архитектура и запахи

- **`db/index.ts`:** ~1 195 строк, 45 методов (Divergent Change).
- **`pipeline.ts` `processJob`:** мутабельный `current` + async `onJoined` (гонка состояний).
- **Мёртвый `assertStatusTransition`:** try/catch делает то же при ошибке перехода.
- **Недостижимый код:** `moveToTranscribing` throw; `zoom-bot` fallback local после docker-only branch; `dockerBin()` не вызывается.
- **Дубли:** retry/transcribe, asana-queue/tracker-create-tasks, putSettings if-блоки.
- **Врущие имена:** `markActionItemsSentToAsana` для ClickUp; `asanaProjectLabel` как GID; `ZOOM_BOT_RUNTIME=auto` ≠ docker.
- **STT:** все сегменты `Спикер 1`; диаризации нет.
- **LLM:** OAuth Claude subscription через API (`anthropic-beta: oauth-2025-04-20`) — риск ToS.
- **Тесты:** проверяют stub-поведение; нет тестов auth scope, OAuth state, settings SSRF, FTS edge cases.

### БД (Postgres / Supabase)

| | |
|---|---|
| Выигрыш | `tsvector` + русский стемминг; `websearch_to_tsquery` (P1-02) |
| Оценка трудозатрат | 3-5 дней + регрессия (`better-sqlite3` sync → async везде) |
