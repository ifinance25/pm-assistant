## Фаза 4. Разделение по спикерам

Делать только после приёмки фазы 3. LLM и текущий Whisper эту фазу не заменяют.

Первый шаг: на живом звонке залогировать `pc.getReceivers()` и посчитать аудиодорожки. Zoom Web SDK часто отдаёт один смешанный поток. От этого зависит, будет ли бонус «дорожка на человека».

Основной путь не зависит от числа дорожек: **таймлайн активного спикера**.

| # | Задача | Деталь | Готово когда |
|---|---|---|---|
| 4.0 | Проверка дорожек | Лог `pc.getReceivers()` на живом звонке: сколько audio track | записан факт: одна дорожка или несколько |
| 4.1 | Сигнал активного спикера | В `capture-audio.js`: `client.on("active-speaker", …)`. Запас: опрос DOM (подсветка плитки говорящего) | в логе меняются имена во время речи |
| 4.2 | Файл таймлайна | Копить `[{ atMs, name }]`, в конце звонка писать `<meetingId>.speakers.json` рядом с wav (`join.mjs`, тот же канал, что `createAudioWriter`) | файл появляется после звонка |
| 4.3 | Склейка с Whisper | Новый `app/src/adapters/stt/diarize.ts`: `assignSpeakers(segments, timeline)` ставит имя того, кто говорил дольше всех в окне сегмента. Нет таймлайна: оставить `Спикер 1` | тест `diarize.test.ts` зелёный |
| 4.4 | Подключить в STT | В `live.ts` убрать хардкод `speaker: "Спикер 1"` (сейчас строки 75 и прогресс в `whisper-progress.ts`) | живая расшифровка несёт имена из таймлайна |

Схему БД не менять: `transcript_segments.speaker` уже есть.

**Бонус (условная ветка, не основной путь):** если 4.0 покажет отдельные дорожки: писать каждую своим `MediaRecorder`, расшифровывать по отдельности, склеивать по таймкодам.

## Фаза 6. Supadata как второй движок

**Заблокирована.** Файл должен быть доступен по публичной ссылке, приложение слушает только `127.0.0.1`. Пока нет решения пользователя: временная ссылка на 15 минут или загрузка в объектное хранилище.

В ответе Supadata поля спикера нет. Имена всё равно проставляет фаза 4.

После снятия блокера:

| # | Задача |
|---|---|
| 6.1 | `app/src/adapters/stt/supadata.ts`: `GET /v1/transcript`, опрос job при 202 |
| 6.2 | Маппинг в `SttSegment`; `SttEngine.kind`: `"whisper-cli" \| "supadata"` |
| 6.3 | Выбор: `PM_ASSISTANT_STT_ENGINE`, по умолчанию `whisper` |
| 6.4 | Проверка тишины и блок-лист **до** отправки наружу |
| 6.5 | Откат на локальный Whisper при ошибке, встречу не ронять |
| 6.6 | Сравнение: `node artifacts/deploy/wer.mjs --engine=supadata` против `--engine=whisper` |
