# PM Assistant — спецификация (утверждена)

**Дата:** 2026-09-03
**Утверждена пользователем:** 2026-09-03
**Источник данных:** [конкурентный обзор](2026-09-03-competitor-analysis-transcription-platforms.md)

> Это не техническое задание для разработки. Это описание того, что должен уметь продукт и в каком порядке важности. Утверждена целиком — следующий шаг: техническая архитектура и выбор стека, отдельный документ.

---

## 1. Проблема и цель

Ручные заметки со звонков теряют детали, а протокол встречи и список задач занимают время после каждого созвона.

Готовые сервисы не закрывают сценарий полностью:
- западные лидеры (Otter, Fireflies, Fathom, Grain, tl;dv) либо не знают русский язык, либо знают плохо, и ни один не подключается к Яндекс.Телемосту;
- у самого Телемоста расшифровка **есть** («Конспект от Алисы Про»), но только на платных корпоративных тарифах, без программного доступа (API — интерфейс для автоматической работы с сервисом извне) для внешней автоматизации, без реального времени и с удалением записи через 24 часа.

**Цель:** один инструмент, который расшифровывает звонки в Zoom, Google Meet и Телемосте на русском языке, сам достаёт список задач и хранит архив встреч дольше суток. Успех — приложение реально заменяет ручные заметки хотя бы на одном настоящем созвоне.

## 2. Пользователи и сценарии

**Основной пользователь:** только вы. **Решено 2026-09-03: сервис для личного использования** — не для команды, не на продажу. Это меняет часть требований в разделе 4 — см. пометки там.

**Сценарий:**
1. Вы подключаете запись к звонку (бот заходит сам, см. раздел 3). 2. После звонка получаете: расшифровку, короткое саммари на русском, список задач. 3. Список задач одной кнопкой уходит в Asana (менеджер задач, уже подключён в проекте [[Project Management Tools]]).

## 3. Архитектура на уровне продукта

Без технических деталей — только то, что видит пользователь.

```
Звонок в Zoom/Meet/Телемосте
        ↓
Захват звука (способ зависит от платформы — см. ниже)
        ↓
Распознавание речи → текст на русском
        ↓
Разделение по говорящим (диаризация) + автосаммари + список задач
        ↓
Хранение и поиск по архиву встреч  →  выгрузка задач в Asana
```

**Захват звука — один и тот же принцип для всех трёх платформ: бот заходит в звонок как участник и записывает.** Меняется только техническая дверь, через которую бот заходит:
- **Zoom и Google Meet:** бот заходит по ссылке из календаря через официальный API (программный доступ по приглашению) — так же, как работают Otter и Fireflies.
- **Яндекс.Телемост:** официального API для ботов нет — исследование подтвердило: API Телемоста не даёт доступа ни к аудио, ни к списку участников. Поэтому бот заходит по ссылке как обычный гость-участник, так же, как уже делают российские сервисы Speech2Text и mymeet.ai. **Решено 2026-09-03** — приложение на компьютере пользователя (desktop-захват) не делаем.

## 4. Функциональные требования (по убыванию приоритета)

**P0 — без этого продукта нет.** **P1 — нужно для полноценной замены существующих инструментов.** **P2 — полезно, можно отложить на вторую итерацию.**

| ID | Требование | Приоритет |
|---|---|---|
| FR-1 | Бот подключается к Zoom-звонку по календарной ссылке, получает звук и список участников | P0 |
| FR-2 | Бот подключается к Google Meet тем же способом | P0 |
| FR-3 | Бот подключается к звонку в Яндекс.Телемосте по ссылке как обычный участник и записывает звук | P0 |
| FR-4 | Расшифровка на русском языке, целевая точность — не более 10% неверно распознанных слов на реальной записи созвона | P0 |
| FR-5 | Автоопределение языка, включая переключение языка посреди звонка (русский + английские термины) | P0 |
| FR-6 | Диаризация — разделение текста по говорящим, с именами участников | P0 |
| FR-7 | Автоматическое саммари встречи **на русском языке** | P0 |
| FR-8 | Извлечение списка задач из разговора: кто, что, когда | P0 |
| FR-9 | Голосовое или текстовое объявление о записи в начале звонка | P0 |
| FR-11 | Ручная отправка задачи в Asana (кнопка «отправить») | P1 |
| FR-12 | Автоматическая отправка задач в Asana после каждой встречи (включается отдельно) | P1 |
| FR-13 | Хранение расшифровок в базе данных, с полнотекстовым поиском по архиву прошлых встреч | P1 |
| FR-14 | Публичный API и вебхуки (автоматическое уведомление внешних систем о новой записи) для собственных интеграций | P2 (понижено — личному использованию хватает прямой связки с Asana из FR-11/12) |

| FR-16 | В карточке задачи — таймкод (метка времени) и ссылка на момент записи, где это обсуждалось | P1 |
| FR-17 | Расшифровка в реальном времени, по ходу звонка | P2 |

| FR-21 | Настройки приложения (конфигурация) хранятся в базе данных, не в отдельных файлах | P1 |

**Почему именно так.** FR-9 в P0, а не ниже, потому что это не техническая фича, а базовое правило приличия и права участников звонка: без объявления о записи продукта быть не может, даже для личного использования. **Формальный лог согласий (было FR-10) убран** — решено 2026-09-03: сервис личный, вы сами организатор каждого звонка, отдельная система учёта согласий для одного человека избыточна; см. раздел 5 и раздел 6. FR-7 в P0 отдельной строкой, потому что один из конкурентов (Fathom) делает русскую расшифровку, но английское саммари — то есть половинчатое решение не считается выполненным требованием.

## 5. Вне текущего объёма (сознательно не делаем сейчас)

- Поддержка Microsoft Teams — явно не в приоритете по вашему решению.
- Очные встречи и мобильное приложение для записи в переговорной.
- Голосовые отпечатки (voiceprint) как основной способ диаризации — только как возможное P2-улучшение.
- Формальный лог согласий с opt-out-ссылками (было FR-10) — не нужен для личного использования; вы сами организатор каждого звонка и объявляете о записи голосом (FR-9).
- Роли, доступ для нескольких пользователей, тарифы, биллинг, поддержка — сервис только для вас, не продукт на продажу.

### Проверяется тестом на первом шаге реализации — не вопрос к вам

Это не решения, а факты, которые узнаём только проверкой. Отвечать не нужно — просто чтобы не потерялось.

- **Движок распознавания речи.** Кандидаты: MacWhisper (исходный выбор) и GigaAM-v3 (Сбер, бесплатно, по замерам исследования точнее на русском в 2–8 раз). План: собрать 10–20 настоящих записей звонков, прогнать через оба, взять точнее по проценту неверно распознанных слов (WER). Побеждает тот, кто точнее — независимо от того, что было выбрано первым.
- **Диаризация в Телемосте через гостевого бота.** Неизвестно, увидит ли бот имена участников (как в Zoom/Meet) или только смешанный звук без имён. Проверяется на первой тестовой встрече. Если имён нет — запасной план уже есть: участники называют себя в начале записи, дальше имена присваиваются вручную один раз и запоминаются.

## 7. Риски

- **Юридический — осознанно принятый риск, не устранённый.** Решили не спрашивать юриста и не оформлять согласие формально, раз сервис личный (раздел 6). Закон 152-ФЗ и статус голоса как персональных данных это не отменяет — если запись чужого голоса без официального согласия когда-нибудь станет предметом спора, это всё ещё имеет значение. Частично смягчается тем, что движок распознавания выбираем локальный или в РФ (раздел 6), то есть звук за рубеж не уходит.
- **Технический — Телемост может закрыть доступ.** Гостевые боты у конкурентов работают сейчас, но Яндекс может в любой момент заблокировать автоматические подключения — гарантии на будущее нет.
- **Технический — Zoom/Google могут потребовать долгое согласование.** Регистрация OAuth-приложения (способ подключения бота через официальный API) у Zoom и Google обычно проходит проверку перед стартом — закладывать время на это заранее.
- **Продуктовый — Яндекс может сократить наше преимущество.** Если Яндекс откроет API для конспектов или включит функцию на бесплатных аккаунтах, часть дифференциации продукта исчезнет. Стоит периодически проверять справку Яндекс 360.
- **Продуктовый — инфраструктурный риск Recall.ai.** Многие западные конкуренты используют общую инфраструктуру ботов Recall.ai. Если Recall.ai добавит поддержку Телемоста, за ним быстро подтянутся крупные западные сервисы — окно возможностей на этом рынке может закрыться быстрее, чем кажется сейчас.

## 9. Глоссарий

- **API** — интерфейс для автоматического, программного доступа к сервису извне (не через кнопки, а через код).
- **Бот** — автоматическая программа, которая заходит в звонок как участник, чтобы записать его.
- **Диаризация** — разделение расшифровки по говорящим: кто что сказал.
- **WER (word error rate)** — доля неправильно распознанных слов; чем меньше, тем точнее распознавание.
- **MCP** — протокол, который позволяет ИИ-ассистентам (например, Claude) напрямую обращаться к данным приложения.
- **Real-time / post-call** — расшифровка по ходу звонка (в реальном времени) или только после его окончания.
- **152-ФЗ** — российский закон о персональных данных.
- **MIT-лицензия** — тип лицензии на программу/модель, разрешающий свободное использование, включая коммерческое, бесплатно.
- **OAuth** — способ, которым сторонняя программа (например, наш бот) получает ограниченный доступ к чужому сервису (например, к календарю Zoom) с разрешения пользователя.
