## Вывод по Yandex Telemost (главный вопрос)

### Прямой ответ: ДА, есть — но с существенными ограничениями

У Яндекс Телемоста **есть встроенная функция расшифровки и конспектов встреч**. Она называется **«Конспект встречи от Алисы Про»**.

**Дата появления фичи:** анонс — **16 апреля 2025 года** (официальный пресс-релиз Яндекса). Раскатка: для малого и среднего бизнеса — с 15 апреля 2025, для крупных организаций — с 26 мая 2025. По состоянию на сентябрь 2026 функция действует и описана в актуальной справке Яндекс 360.

**Что именно она делает** (по официальной справке Яндекса):
- Краткий пересказ основных идей и тем встречи.
- Раздел **«Задачи»** — список договорённостей (то есть action items, задачи из разговора, уже есть).
- Полная расшифровка речи с временными метками (тайм-кодами) — приходит вложением к письму.
- Технологии: распознавание речи Яндекса + суммаризация нейросетью YandexGPT.

**Критические ограничения — именно здесь остаётся место для нашего продукта:**

| Ограничение | Детали |
|---|---|
| **Только корпоративные аккаунты** | Тарифы Яндекс 360: Минимальный, Основной, Продвинутый, Корпоративный. Личным аккаунтам вида `login@yandex.ru` функция **недоступна** |
| **Нет API** | Прямая цитата из справки: «Нельзя включать или настраивать конспектирование встреч с помощью API». Автоматизировать снаружи нельзя |
| **Не в реальном времени** | Результат приходит после встречи. По независимому обзору CogniCo (28.02.2026) — «в течение нескольких часов», не мгновенно. *Требует проверки на практике* |
| **Гости не получают конспект** | Участники вне организации исключены из рассылки |
| **Запись живёт 24 часа** | «Записи встреч хранятся в защищённом хранилище 24 часа, пока конспект готовится, а после безвозвратно удаляются». То есть архива записей нет — только текст |
| **Включает только организатор** | По умолчанию — организатор и соорганизаторы; права можно расширить вручную |
| **Платно** | Тариф Минимальный — 485 ₽/сотрудник/мес с 01.07.2026 (*вторичный источник, требует проверки на официальной странице тарифов*) |

**Диаризация (разделение по говорящим):** по обзору CogniCo — есть, «с привязкой реплик к конкретным участникам». **Официальная справка Яндекса это явно не подтверждает.** *Требует проверки — надо просто провести тестовую встречу.*

### Что это значит для проекта

Идея «своего приложения для Телемоста» **не умирает, но её позиционирование меняется**. Нельзя больше продавать «мы дадим вам расшифровку Телемоста» — Яндекс уже даёт. Продавать надо то, чего у Яндекса нет:

1. **Работа на бесплатных/личных аккаунтах** — огромный сегмент, который Яндекс отрезал.
2. **API и интеграции** — Яндекс явно закрыл эту дверь. Выгрузка задач в Asana/Jira/Trello из Телемоста невозможна штатно.
3. **Реальное время** — Яндекс отдаёт результат часами позже.
4. **Единый продукт для Zoom + Meet + Телемост** — у Яндекса конспекты только внутри своей экосистемы; у западных — только Zoom/Meet/Teams. Никто не закрывает все три сразу.
5. **Хранение и поиск по архиву встреч** — Яндекс удаляет записи через 24 часа.

**Но:** это поле **уже не пустое**. См. раздел про русскоязычный рынок — есть минимум 3 российских сервиса, которые уже подключаются к Телемосту.

**Дополнительное подтверждение на уровне инфраструктуры.** Большинство западных сервисов не пишут ботов сами, а используют **Recall.ai** — это «API ботов для встреч», инфраструктурный слой под капотом у десятков продуктов. Официальная документация Recall.ai перечисляет: Zoom, Google Meet, Microsoft Teams, Webex, GoTo Meeting (бета). **Telemost и вообще Yandex там отсутствуют.** Это значит, что даже если какой-то западный стартап захочет добавить Телемост завтра, готовой инфраструктуры под это нет — придётся строить с нуля.

**Причина, по которой это так, а не иначе:** у Телемоста **нет публичного bot API**. Официальный API Яндекс Телемоста (`yandex.ru/dev/telemost`) даёт ровно три права доступа: создание встреч и трансляций, просмотр данных о встречах, редактирование данных о встречах. **Ни подключения бота к конференции, ни доступа к аудиопотоку, ни получения записи или транскрипта в нём нет.** Это подтверждает исходное решение проекта делать для Телемоста отдельное десктоп-приложение с захватом системного звука.

## Разбор по каждой платформе

### Otter.ai

**Сильные стороны**
- Единственный в подборке с по-настоящему хорошей расшифровкой **в реальном времени** — текст появляется по ходу встречи, есть живые субтитры и голосовые команды прямо в звонке.
- Захват слайдов из демонстрации экрана.
- Самый широкий набор сертификаций: SOC 2 Type 2, GDPR, CCPA, HIPAA, ISO 27001/2, VPAT.
- Развитая экосистема интеграций с таск-трекерами (Jira, Notion, ClickUp, Asana).

**Слабые стороны**
- **Русского языка нет вообще.** Поддерживаются только английский, испанский, французский, немецкий, японский и китайский. Для нашего продукта это **дисквалифицирующий фактор** — Otter выбывает как прямой конкурент на российском рынке и остаётся только как источник UX-идей.
- Нативная интеграция с Asana — только на Enterprise; на Pro/Business придётся платить ещё и за Zapier.
- API слабый, документация скудная, доступ фактически enterprise-only.
- Обучает свои модели на обезличенных пользовательских данных **по умолчанию**.
- Данные только в США, выбора региона нет.
- Жёсткие лимиты: 300 мин/мес на бесплатном, 90 минут на один разговор на Pro.

**Что взять на заметку**
- **Real-time — это их главный и почти уникальный козырь.** Если мы сделаем живую расшифровку на русском, у нас будет то, чего нет ни у кого на российском рынке (ни у Телемоста, ни у mymeet, ни у Speech2Text — все отдают результат после звонка).
- Захват слайдов — недорогая, но заметная фича для PM-сценария: протокол с картинками из презентации.

### Fireflies.ai

**Сильные стороны**
- **Лучшая в подборке механика согласия на запись.** Письмо всем приглашённым за час до встречи с предупреждением о записи + ссылка «отказаться» (тогда бот не придёт) + возможность выгнать бота из звонка. Это готовая, отработанная UX-модель.
- **Полноценный публичный GraphQL API** — транскрипты, метаданные, поиск, саммари, action items, аналитика по спикерам, управление встречами.
- Самый широкий список платформ: 9 сервисов ВКС + телефонные диалеры (Aircall, RingCentral).
- **Гибридный захват**: бот + десктоп-приложение с захватом системного звука + расширение + загрузка файлов. Это ровно та архитектура, которую заложил наш проект.
- Русский официально в списке 100+ языков.
- Автоматическое создание задач в Asana.

**Слабые стороны**
- **Качество русского заметно ниже английского** — это признаётся и в обзорах, и косвенно самим вендором. В независимом (хотя и вендорском) тесте tl;dv на русском Fireflies занял 3-е место из 4.
- **Ключевая находка для нашей архитектуры:** при захвате системного звука через десктоп-приложение **диаризация ломается** — говорящие обозначаются как «Speaker 1 / Speaker 2» без имён. Имена появляются только когда в звонке сидит бот и видит список участников. Это **прямое предупреждение для нашего сценария с Телемостом**.
- Нет русской локализации интерфейса, нет автоопределения языка на базовых тарифах.
- API только с тарифа Business ($19–29/польз./мес) — дорогой порог входа.
- Бесплатный тариф почти бесполезен: 400 минут на всю команду и запрет на скачивание транскрипта.
- Не работает оплата российскими картами / СБП (*вторичный источник, требует проверки*).

**Что взять на заметку**
- **Скопировать модель согласия на запись целиком** — письмо заранее + opt-out ссылка + кнопка «выгнать». Это и юридически грамотно, и снимает главное социальное трение при внедрении.
- **Проблема диаризации при системном захвате — наш риск №1 по Телемосту.** Надо решать заранее, до разработки (варианты в рекомендациях).
- GraphQL API — хороший образец схемы данных: recording → transcript → summary → action items → speaker analytics.

### Fathom

**Сильные стороны**
- **Самый щедрый бесплатный тариф в индустрии**: безлимитные записи, расшифровки и хранение.
- Очень быстрая пост-обработка — саммари готово примерно через 30 секунд после окончания звонка.
- Качество саммари стабильно называют одним из лучших в категории; чёткая структура: ключевые моменты / решения / action items.
- **Есть публичный API и MCP-сервер** (протокол подключения ИИ-ассистентов вроде Claude и ChatGPT к внешним данным) — современный подход.
- **Режимы захвата без бота**: только транскрипт без записи, локальный захват аудио без видео, или полноценный бот с видео. Выбор режима — для каждой встречи отдельно.
- SOC 2 Type II, GDPR, HIPAA; есть возможность отказаться от использования данных для обучения моделей.

**Слабые стороны**
- **Критично для нас: саммари на русском нет.** Транскрипция русского работает (38 языков), но автоматический перевод саммари сделан только для 6 языков — испанский, португальский, немецкий, французский, итальянский, нидерландский. **Русского там нет** → протокол встречи придёт на английском. Для русскоязычной команды это ломает основной сценарий.
- В тесте tl;dv на русскоязычных встречах Fathom занял **последнее, 4-е место** (83 из 200 баллов, из них за точность транскрипции — 14 из 65). Тест вендорский, но разрыв слишком велик, чтобы его игнорировать.
- Режим без бота — бета, **только Mac и только английский язык**.
- Все данные в США, EU-резидентности нет.
- Противоречие в источниках по лимиту AI-саммари на бесплатном плане: официальная страница тарифов говорит про автоматические AI-саммари без оговорок, сторонние обзоры — про лимит 5 саммари в месяц. *Требует проверки.*

**Что взять на заметку**
- **Модель «выбор режима захвата для каждой встречи»** — отличная идея для чувствительных разговоров. Три уровня: «только текст без записи» / «локальное аудио без видео» / «бот с видео». Это снимает возражение «я не хочу, чтобы наш созвон утёк».
- Бесплатный безлимит на записи как инструмент захвата рынка.
- Публичный API + MCP как стандарт 2026 года — стоит закладывать MCP-сервер в спецификацию сразу.

### tl;dv

**Что взять на заметку**

- **EU data residency как продукт** — доказательство, что «где лежат данные» продаётся как отдельная ценность. Для нас аналог — «данные в РФ».

## Русскоязычный рынок и выбор движка распознавания

### Yandex SpeechKit

**Цена.** Единица тарификации — **отрезок 15 секунд** одноканального аудио. По вторичным источникам (август 2026): базовая модель — **10 ₽/мин**, премиум с эмоциями — 20 ₽/мин, с пользовательскими словарями — 30 ₽/мин. Синтез речи — 400 ₽ за 1 млн символов.
*Требует проверки: официальная страница тарифов Yandex AI Studio при обращении 03.09.2026 отдавала CAPTCHA, цифры взяты из вторичных обзоров. Перед бюджетированием — сверить на `aistudio.yandex.ru/docs/ru/speechkit/pricing`.*

**Прикидка для нашего сценария.** При 10 ₽/мин один часовой созвон = **600 ₽**. Команда из 10 человек с 5 встречами по часу в неделю = 50 часов/мес = **30 000 ₽/мес** только за распознавание, без учёта суммаризации. Для сравнения: Deepgram Nova-3 — $0.0043/мин (~0.35 ₽/мин по курсу), AssemblyAI — от $0.0025/мин (~0.20 ₽/мин). **SpeechKit дороже западных облаков примерно в 25–50 раз.** Это делает его практически неприменимым как основной движок для массового продукта.

**Режимы работы:**
- Синхронный — короткие фразы.
- Асинхронный (отложенный) — файлы **до 4 часов**, до 60 МБ в теле запроса или до 1 ГБ через загрузку в бакет; результат хранится на сервере **3 дня**.
- Потоковый — текст появляется по ходу записи (это то, что нужно для real-time).

**Точность.** Вендор заявляет 95%+ на русском. **Независимая проверка даёт менее радужную картину.** Сравнительный тест SimbirSoft (Хабр, 14.08.2024), метрика WER (word error rate — доля неверно распознанных слов, чем меньше тем лучше):

| Условия | SpeechFlow | SaluteSpeech | **Yandex SpeechKit** |
|---|---|---|---|
| Естественная речь, нормальный темп | 0.20 | 0.24 | **0.31** |
| С фоновым шумом | 0.24 | 0.26 | **0.63** |
| Ускорение в 2 раза | 0.62 | 0.98 | **0.92** |

Выводы авторов: SpeechKit **игнорирует пунктуацию и очень чувствителен к шуму**. WER 0.63 в шуме означает, что каждое второе слово распознано неверно — для реального созвона с открытым микрофоном это неприемлемо.
*Оговорка: тест от августа 2024, модели с тех пор обновлялись. Требует перепроверки на актуальной версии.*

**Готовые кейсы.** Основной публичный сценарий SpeechKit — **распознавание телефонных звонков и аналитика колл-центров**, а не расшифровка видеовстреч. Кейсов именно по созвонам в публичном поле мало.

### Sber SaluteJazz — да, встроенный аналог есть

Отвечая прямо на вопрос: **у SaluteJazz есть встроенная расшифровка и протокол встреч.**

- **Транскрибация включается автоматически**, как только к встрече подключается второй участник. Работает на собственной технологии SberDevices **SmartSpeech**, заявлено хорошее распознавание имён, сложных терминов и длинных слов.

- Работает в web, desktop и мобильной версиях.
- **Доступна только организаторам с бизнес-лицензией.**
- Диаризация в документации не упоминается — *требует проверки*.
- Про место хранения данных и API в справке ничего нет — *требует проверки*.

**Вывод:** структура ограничений почти зеркальная Телемосту — фича есть, но только для платных бизнес-аккаунтов и только внутри своей экосистемы. Это подтверждает общий паттерн российского рынка: **крупные платформы закрывают базовый сценарий для своих платящих корпоративных клиентов и не открывают API наружу.**

### GigaAM-v3 — главная находка исследования по движку распознавания

**Это, вероятно, самое важное для спецификации продукта, что нашлось.**

**Что это.** Сбер 15 декабря 2025 года выложил в открытый доступ семейство моделей распознавания русской речи **GigaAM-v3** — веса и код **под лицензией MIT** (свободное коммерческое использование). Архитектура Conformer, 220 млн параметров, предобучение на **700 000 часов русской речи**. Доступно на HuggingFace (`ai-sage/GigaAM-v3`).

**Варианты моделей:** `ssl` (энкодер), `ctc`, `rnnt`, `e2e_ctc` и `e2e_rnnt` — последние два **сразу выдают текст с пунктуацией и нормализацией** (числа, даты, сокращения приводятся к читаемому виду).

**Бенчмарки против Whisper large-v3 на русском** (WER, меньше = лучше; данные от Сбера):

| Датасет | GigaAM-v3 RNNT | Whisper large-v3 | Разница |
|---|---|---|---|
| Golos Farfield (дальний микрофон) | **3.9%** | 16.4% | в 4.2 раза лучше |
| Golos Crowd | **2.4%** | 19.0% | в 7.9 раза лучше |
| Russian LibriSpeech | **4.4%** | 9.4% | в 2.1 раза лучше |
| Common Voice 19 | **0.9%** | 5.4% | в 6 раз лучше |
| Natural Speech (естественная речь) | **6.9%** | 13.4% | в 1.9 раза лучше |
| Disordered Speech (нарушения речи) | **19.2%** | 58.6% | в 3.1 раза лучше |
| **Callcenter (звонки)** | **9.5%** | 23.1% | **в 2.4 раза лучше** |

Строка **Callcenter — самая релевантная для нас**: это ближайший аналог реального созвона со сжатым звуком и перебиваниями.

**Независимое подтверждение.** Отдельный тест на Хабре (21.02.2026): GigaAM v3-e2e-rnnt — **WER 3.3% на обычном CPU**, против Whisper large-v3-turbo — 7.9% **на видеокарте RTX 4090**. То есть модель точнее и при этом не требует GPU.
*Важная оговорка: в этом тесте использовались всего 5 фрагментов из аудиокниг, синтезированных через TTS (генератор речи), а не реальные записи встреч. На реальном звуке с перебиваниями, эхом и фоновым шумом цифры будут заметно хуже у всех моделей. Требует собственной проверки.*

**Ограничения GigaAM-v3:**
- **Диаризации в модели нет.** Разделение по говорящим придётся делать отдельным модулем (например, pyannote).
- Только русский язык — для смешанных русско-английских встреч нужна либо вторая модель, либо гибридная схема. *Требует проверки, как GigaAM ведёт себя на английских вставках.*
- Требования: Python 3.10+, ffmpeg.

**Что это значит для решения по движку.** Зафиксированный кандидат проекта — **MacWhisper на WhisperKit Large v3 Turbo**. Если верить и вендорским, и независимым замерам, **GigaAM-v3 обгоняет Whisper large-v3 на русском в 2–8 раз по WER, при этом бесплатен (MIT), работает на CPU и уже умеет пунктуацию.** Это не повод отменять решение, но **это повод провести собственный замер до старта разработки** — цена ошибки здесь высокая, качество распознавания русского объявлено приоритетом №1 проекта.

**Общий вывод по рынку.** Российский рынок расслоился на три пласта:
1. **Платформы ВКС** делают базовую расшифровку для своих платящих корпоративных клиентов, без API, медленно, каждая в своём загоне.
2. **Мелкие сервисы-боты** (mymeet, Speech2Text, Конспектор) закрывают кросс-платформенность, но слабы по продукту, интеграциям и бренду.
3. **Западные лидеры** (tl;dv, Fireflies) сильны по продукту, но не поддерживают Телемост, плохо знают русский и **юридически проблемны по 152-ФЗ**.

Ниша «сильный продукт + все три платформы + русский на уровне SOTA + данные в РФ + API и Asana» — **не занята**.

## Открытые вопросы к юристу / требует дополнительной проверки

> ⚠️ **Ниже — краткое резюме найденных публикаций, а НЕ юридическое заключение. Все пункты обязательно проверить с профильным юристом по персональным данным до запуска продукта.**

### 1. Запись голоса — это персональные данные, а возможно и биометрия

- Аудиозапись переговоров может быть отнесена к **биометрическим персональным данным**, поскольку голос характеризует физиологические особенности человека и по нему можно установить личность.
- Биометрические ПД по общему правилу обрабатываются **только при письменном согласии** субъекта.
- **Спорный момент:** если голос не используется для установления личности, ряд источников считает, что запись биометрией не является. Единой практики нет.
- Даже если это не биометрия — это всё равно **обработка персональных данных**, и на неё нужно правовое основание: согласие, исполнение договора или законный интерес оператора.
- **Вопрос юристу:** является ли транскрипт делового созвона с диаризацией по именам участников биометрическими ПД? Нужно ли письменное согласие каждого участника, включая внешних гостей?

### 2. Локализация данных — главный юридический риск для западных сервисов

- С **1 июля 2025 года** действует обновлённая **часть 5 статьи 18 152-ФЗ**, которая прямо закрепляет **запрет на первичный сбор персональных данных граждан РФ с использованием иностранных хранилищ**.
- По разбору юристов, **любая передача ПД в систему зарубежного провайдера, при которой данные записываются в иностранной базе — пусть временно и в целях обработки — образует нарушение** ч. 5 ст. 18.
- Из нормы **исключено упоминание операторов ПД**, что, вероятно, распространяет обязанность и на лиц, обрабатывающих данные **по поручению** оператора.
- Трансграничная передача **после** первичного сбора в российскую базу — допускается.
- **Практический вывод (требует подтверждения юристом):** отправка аудио русскоязычного делового созвона напрямую в Otter / Fireflies / Fathom / Grain / tl;dv / MeetGeek с высокой вероятностью нарушает ч. 5 ст. 18 152-ФЗ, поскольку первичная запись оказывается на серверах в США/ЕС. **Ни одна из шести платформ не предлагает размещение данных в РФ** — это подтверждённый факт, а не предположение.
- **Вопрос юристу:** достаточно ли схемы «первичная запись на нашем сервере в РФ → затем передача текста в зарубежный LLM для суммаризации» для соблюдения ч. 5 ст. 18? Какие условия трансграничной передачи нужно соблюсти?

### 3. Уведомление Роскомнадзора

- Помимо уведомления участников и получения согласия, компания обязана **заблаговременно уведомить Роскомнадзор** о намерении осуществлять обработку персональных данных.
- **Вопрос юристу:** нужно ли нам как разработчику подавать уведомление, и в какой роли мы выступаем — оператор ПД или обработчик по поручению клиента?

### 4. Ответственность и штрафы

- Передача записей третьим лицам без согласия субъекта ПД квалифицируется как нарушение — **штраф от 300 000 до 700 000 ₽ для юридических лиц**.
- **Вопрос юристу:** является ли передача аудио в зарубежный API «передачей третьим лицам»? Как распределяется ответственность между нами и клиентом?

### 5. Не исследованные аспекты — требуют отдельной проработки

- **Ст. 137 УК РФ** (нарушение неприкосновенности частной жизни) применительно к записи деловых созвонов — **не исследовано**.
- Требования к **согласию несовершеннолетних** и к записи с участием представителей госорганов — **не исследовано**.
- Отраслевые ограничения (банковская, врачебная, адвокатская тайна) — **не исследовано**.
- Нужна ли **сертификация ФСТЭК / включение в реестр отечественного ПО** для продаж в госсектор — **не исследовано**. Референс: VOICEE уже в реестре российского ПО, это даёт им преимущество в госзакупках.

## Рекомендации для спецификации нашего продукта

### A. Позиционирование — скорректировать формулировку по Телемосту

Утверждение «у Телемоста нет расшифровки» **неверно и его нельзя использовать в продуктовых материалах**. Верная формулировка:

> «У Телемоста расшифровка есть, но только для платных корпоративных аккаунтов, без API, без реального времени, без гостей, и с удалением записи через 24 часа.»

Пять точек атаки, вытекающих напрямую из ограничений Яндекса:
1. Работа на **личных и бесплатных** аккаунтах Телемоста.
2. **API и автоматическая выгрузка задач** — дверь, которую Яндекс закрыл явно и полностью.
3. **Реальное время** вместо «через несколько часов».
4. **Единый продукт для Zoom + Meet + Телемост** — ни один игрок в мире этого не делает.
5. **Архив и сквозной поиск по всем встречам** — Яндекс удаляет записи через сутки.

### B. Движок распознавания — провести замер до фиксации выбора

**Не отменять MacWhisper, но обязательно сравнить с GigaAM-v3 перед разработкой.** Основание: по всем найденным замерам (и вендорским, и независимым) GigaAM-v3 обгоняет Whisper large-v3 на русском в 2–8 раз по WER, распространяется по MIT (бесплатно, коммерчески), работает на CPU и выдаёт пунктуацию из коробки.

Протокол собственного бенчмарка:
1. Собрать **10–20 реальных записей созвонов** — с перебиваниями, разным качеством микрофонов, английскими терминами.
2. Сделать эталонные расшифровки вручную.
3. Прогнать: MacWhisper (WhisperKit large-v3 turbo), GigaAM-v3 e2e-rnnt, Deepgram Nova-3, AssemblyAI, Yandex SpeechKit.
4. Метрики: **WER**, качество пунктуации, точность на англоязычных вставках, скорость, стоимость минуты.
5. Критерий успеха: **WER ≤ 10% на реальном созвонном аудио.**

Ожидаемый исход (гипотеза для проверки): **GigaAM-v3 локально как основной движок для русского + Whisper как запасной для смешанных русско-английских встреч.** Это даёт нулевую переменную стоимость распознавания и полное отсутствие передачи данных наружу — сразу закрывает и экономику, и юридический риск по 152-ФЗ.

### C. Диаризация — заложить как отдельный модуль, а не считать «встроенной»

**Риск №1 всей архитектуры.** Подтверждённый факт: у Fireflies при захвате системного звука через десктоп-приложение **диаризация деградирует до «Speaker 1 / Speaker 2» без имён**. Это ровно наш сценарий с Телемостом. GigaAM-v3 диаризацию тоже не включает.

Варианты решения, в порядке предпочтения:
1. **Сопоставление с участниками через API Телемоста** — «Просмотр данных о встречах» есть в списке прав OAuth. *Требует проверки: отдаёт ли API список участников встречи.*
2. **Предварительная регистрация голосов (voiceprint)** — участник один раз наговаривает образец, дальше система узнаёт его по голосу.
3. **Разделение говорящих аудио-моделью** (pyannote или аналог) + **ручное присвоение имён после первой встречи**, с запоминанием на будущее. Самый реалистичный MVP.
4. Для Zoom и Meet, где мы идём через официального бота, — брать имена из списка участников напрямую.

### D. Данные — размещение в РФ как продуктовая функция №1

Подтверждённый факт: **ни одна из шести западных платформ не предлагает размещение данных в России и никак не адресует 152-ФЗ.** При этом с 1 июля 2025 первичный сбор ПД граждан РФ на иностранных серверах прямо запрещён.

Это не «галочка комплаенса», а **главное конкурентное преимущество**. Референс — tl;dv, который продаёт «EU data residency» как отдельную ценность.

Требования к архитектуре:
- Первичная запись и распознавание — **на инфраструктуре в РФ** (или локально на машине пользователя, что ещё лучше).
- **Локальный движок распознавания (GigaAM) снимает вопрос полностью** — аудио вообще никуда не уходит.
- Если для суммаризации нужен внешний LLM — рассмотреть YandexGPT или GigaChat вместо OpenAI/Anthropic, либо локальную модель.
- Явно указать в маркетинге: обработка и хранение на серверах в РФ. Так делают Конспектор, mymeet, Speech2Text — это уже стало гигиеническим требованием рынка.
- Рассмотреть **включение в реестр российского ПО** (референс: VOICEE) — открывает госсектор.

### E. Интеграция с Asana — скопировать двухуровневую модель MeetGeek

Найденный факт: MeetGeek — единственный из шести с нативной интеграцией, опубликованной в собственном каталоге приложений Asana. Механика:
- **Ручная отправка** («поделиться встречей» → выбрать workspace/команду/проект/секцию) — **доступна на всех планах, включая бесплатный**.
- **Автоматические сценарии** («после каждой встречи создать задачи») — с платного тарифа.

Это правильная монетизация: пользователь бесплатно убеждается, что связка работает, и платит за то, чтобы не нажимать кнопку.

Дополнительно:
- Отдавать не только текст задачи, но и **ответственного и срок** (референс: Конспектор уже это делает).
- В примечание к задаче класть **тайм-код и ссылку на фрагмент** записи, чтобы можно было проверить контекст.
- Отсутствие нативной Asana у Grain, tl;dv и Fathom — **наша дифференциация**.

### F. Согласие на запись — взять модель Fireflies целиком

Лучшая найденная практика (Fireflies):
1. Письмо всем приглашённым **за час до встречи**: «встреча будет записана».
2. В письме — **ссылка «отказаться»**: если нажали, бот не приходит.
3. **Запрос в момент начала встречи**, который можно отклонить.
4. Бот **виден в списке участников**, его можно выгнать в любой момент.

Дополнить с учётом РФ:
- **Голосовое или текстовое объявление в начале записи** (рекомендация справки Grain).
- Хранить **лог согласий** — кто, когда и как согласился. Это понадобится при проверке.
- Заимствовать у Fathom **выбор режима для каждой встречи**: «только текст без сохранения записи» / «локальное аудио без видео» / «полная запись». Снимает главное возражение при внедрении.

### H. Тарифная сетка — ориентиры по рынку

- **Бесплатный тариф обязателен.** Планка на российском рынке: mymeet — 180 мин/мес, Speech2Text — 180 мин, Конспектор — 1 встреча до 60 мин. Планка у западных: tl;dv и Fathom — безлимит записей.
- **Если движок локальный (GigaAM), переменная стоимость близка к нулю** — можно позволить себе агрессивно щедрый бесплатный тариф уровня Fathom/tl;dv и забрать рынок у российских сервисов, которые платят за облачное распознавание.
- **Ценовой коридор российского рынка:** 500–2400 ₽/мес. Западные — $10–59/польз./мес (900–5300 ₽). Мы можем встать в 700–1500 ₽/польз./мес и быть дешевле западных при лучшем русском.
- **Взять модель доплаты за перерасход** ($0.50/час у MeetGeek) вместо жёсткой блокировки — «встреча не записалась, лимит кончился» это одна из главных болей в отзывах на конкурентов.

**Прямые конкуренты по Телемосту (уже на рынке):** Speech2Text, mymeet.ai, Конспектор (telesummary.ru), WonderScribe.
**Прямой конкурент по русскому языку из западных:** tl;dv — единственный с полноценным русским и EU-резидентностью.

---

**Три вещи, которые я бы вынес из этого исследования как самые важные:**

1. **Телемост уже умеет расшифровку и конспекты с апреля 2025** — но только на платных корпоративных тарифах, без API, без реального времени и с удалением записи через 24 часа. Позиционирование продукта надо переписать под эти конкретные дыры.
2. **Гипотеза подтвердилась на 100%: ни одна из 6 западных платформ не поддерживает Telemost**, и на уровне инфраструктуры (Recall.ai) поддержки тоже нет. Но поле не пустое — 3-4 российских сервиса уже туда зашли.
3. **GigaAM-v3 от Сбера (MIT, декабрь 2025) обгоняет Whisper large-v3 на русском в 2–8 раз по WER, бесплатен и работает на CPU.** Это ставит под вопрос выбор MacWhisper и требует собственного замера до старта разработки.
