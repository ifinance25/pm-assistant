# Спецификация: подключение Google Календаря

**Дата:** 2026-09-05
**Версия:** 1.0, черновик на утверждение
**Аналог:** [fireflies.ai](https://fireflies.ai/), раздел Calendar / Upcoming meetings
**База:** ADR `.autopilot/spec.md` §8 (один Google OAuth client), `artifacts/2026-09-04-fireflies-ux-10-edits.md`, `artifacts/2026-09-05-v2-ui-implementation-handoff.md` §3.5 и §4.8

---

## 0. Зачем

На экране `/settings` в блоке «Интеграции» есть кнопка «Подключить Google Календарь». Сейчас она ничего не делает: сервер отвечает заглушкой `{stub: true, notice: "заглушка: Google Календарь не подключён"}` (`app/src/server/routes/integrations.ts:58-66`), флаг `googleCalendar` в сессии всегда `false`, страница `/calendar` показывает баннер «Живой календарь в этой версии не подключается».

Живой Google OAuth (протокол входа через чужой аккаунт) в проекте уже работает для входа в приложение: `app/src/server/routes/auth.ts:201-315`. Календарь переиспользует тот же OAuth client.

**Объём выбран владельцем продукта 2026-09-05: только чтение календаря.** Бот сам никуда не заходит. В список попадают все встречи со ссылкой на звонок.

---



## 1. Что человек видит и делает

Поток из пяти шагов, как в Fireflies:

1. Настройки, блок «Интеграции», кнопка «Подключить Google Календарь».
2. Браузер уходит на страницу согласия Google. Пользователь выбирает аккаунт и разрешает читать календарь.
3. Google возвращает обратно на `/settings#integrations`. Статус меняется на «подключён», рядом видна почта аккаунта.
4. Экран `/calendar` вместо баннера «выключен» показывает встречи из Google Календаря на 7 дней вперёд. У каждой: название, время, платформа, ссылка.
5. У встречи есть кнопка. Если бот на неё ещё не ходил, кнопка «Отправить бота» создаёт встречу и уводит на её экран. Если встреча уже в базе, кнопка «Открыть» ведёт на расшифровку.

Отключение: кнопка «Отключить» в тех же Настройках. Токен удаляется, `/calendar` возвращается к прежнему баннеру.

**Отличие от Fireflies, осознанное:** бот не заходит на встречи сам. Правила авто-подключения, галочки «записывать эту встречу» и вход за 2 минуты до начала в объём не входят.

## 3. Точки входа HTTP


| Метод  | Путь                                         | Что делает                                                                                            | Ответ                                                                |
| ------ | -------------------------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| GET    | `/api/integrations/google-calendar/start`    | Кладёт `state` в cookie, редиректит на `accounts.google.com`                                          | 302, либо 503 если нет `GOOGLE_CLIENT_ID`                            |
| GET    | `/api/integrations/google-calendar/callback` | Сверяет `state`, меняет `code` на токены, читает почту через `userinfo`, пишет в `integration_tokens` | 302 на `/settings#integrations`, при ошибке `?error=google-calendar` |
| DELETE | `/api/integrations/google-calendar`          | Удаляет токен. **Уже реализовано**                                                                    | `{ok: true, connected: false}`                                       |
| GET    | `/api/calendar/events`                       | Отдаёт события на 7 дней вперёд                                                                       | `CalendarFeed`, см. раздел 4                                         |


`/api/calendar/events` возвращает 200 всегда, даже когда календарь не подключён. Состояние описывают поля ответа, а не код ошибки. Так интерфейсу не надо разбирать коды.

Отдельный публичный доступ к callback не нужен: пользователь на этом шаге уже вошёл в приложение, cookie сессии уходит вместе с редиректом (`SameSite=Lax` это разрешает).

## 4. Типы

Добавить в `app/src/shared/types.ts`:

```ts
export type CalendarEvent = {
  id: string;                        // id события в Google
  title: string;
  startsAt: string;                  // ISO
  endsAt: string | null;
  url: string;                       // ссылка на звонок
  platform: Platform;                // zoom | meet | telemost
  supported: boolean;                // false для meet и telemost
  meetingId: string | null;          // если встреча уже в базе
  meetingStatus: MeetingStatus | null;
};

export type CalendarFeed = {
  connected: boolean;
  account: string | null;            // почта аккаунта Google
  expired: boolean;                  // токен протух, нужно подключить заново
  events: CalendarEvent[];
};
```

Поле `SessionInfo.integrations.googleCalendar` уже есть, менять его не нужно. Дополнительно отдавать почту: `googleCalendarAccount: string | null`.

## 5. Данные

**Новых таблиц нет.** События не сохраняются в базу: они читаются у Google при каждом открытии экрана. Так нет расхождения между приложением и календарём и не нужен фоновый синхронизатор.

Таблица `integration_tokens` подходит без миграции (`app/src/db/schema.ts:194-200`):


| Колонка         | Значение для календаря                    |
| --------------- | ----------------------------------------- |
| `provider`      | `google_calendar`                         |
| `access_token`  | токен доступа, живёт 1 час                |
| `refresh_token` | токен обновления                          |
| `expires_at`    | ISO-время, когда `access_token` протухнет |
| `meta_json`     | `{"email": "...", "connectedAt": "..."}`  |


Готовые методы, которые переиспользуются: `upsertIntegrationToken`, `getIntegrationAccessToken`, `isIntegrationConnected`, `deleteIntegrationToken` (`app/src/db/index.ts`).

## 7. Как читаются события у Google

Один запрос:

```
GET https://www.googleapis.com/calendar/v3/calendars/primary/events
    ?timeMin=<сейчас>&timeMax=<сейчас+7дней>
    &singleEvents=true&orderBy=startTime&maxResults=50
Authorization: Bearer <access_token>
```

`singleEvents=true` разворачивает повторяющиеся встречи в отдельные события, иначе еженедельный созвон пришёл бы одной строкой.

Поиск ссылки на звонок в событии, по порядку:

1. `conferenceData.entryPoints[]`, где `entryPointType === "video"`
2. `hangoutLink`
3. `location`
4. первый адрес в `description`

Каждый кандидат прогоняется через готовую `detectPlatform` (`app/src/adapters/platform/detect.ts:3-24`). Если она вернула `null`, кандидат отбрасывается. Событие без единой подходящей ссылки в список не попадает.

Обновление токена: если `expires_at` в прошлом или наступит в ближайшую минуту, идёт `POST https://oauth2.googleapis.com/token` с `grant_type=refresh_token`, новый токен пишется в базу. Если Google ответил ошибкой, токен удаляется и ответ помечается `expired: true`.

## 8. Что нужно сделать в Google Cloud Console

Ручные шаги пользователя, без них кнопка не заработает. Тот же проект и тот же OAuth client, что для входа.

1. Включить Google Calendar API в проекте.
2. На экране согласия добавить разрешение `https://www.googleapis.com/auth/calendar.events.readonly`.
3. В OAuth client добавить второй адрес возврата: `http://127.0.0.1:8787/api/integrations/google-calendar/callback`
4. В разделе Test users добавить свою почту.
5. В `.env` положить `PM_ASSISTANT_GOOGLE_CALENDAR_REDIRECT_URI` с тем же адресом.

## 9. Честные ограничения

- **Раз в 7 дней придётся подключать заново.** Пока приложение в Google Cloud Console стоит в режиме Testing, refresh-токен живёт 7 дней. Чтобы этого не было, приложение надо провести через проверку Google, а это отдельная работа на недели. Для личного сервиса разумнее мириться и нажимать «Подключить» раз в неделю.
- **Предупреждение «Google hasn't verified this app».** На экране согласия будет жёлтая плашка. Пройти через «Advanced» и «Go to PM Assistant». Следствие того же режима Testing.
- **Кнопка «Отправить бота» работает только для Zoom.** Google Meet и Телемост сервер отклоняет с 503 (`app/src/server/routes/meetings.ts:76-81`). Живой вход туда это отдельная задача, уже записанная в Next Actions.
- **Токен один на приложение.** У `integration_tokens` первичный ключ это `provider`, привязки к пользователю нет. Для личного сервиса на одного человека это верно; при втором пользователе понадобится миграция.
- **Существующая ссылка** `/?url=...` **на экране календаря мертва.** Главная не читает параметр `url` из адреса. Поэтому новая кнопка шлёт `POST /api/meetings` напрямую, а не переводит на Главную. Проект берётся из `localStorage` (ключ тот же, что у Главной), иначе проект по умолчанию.

## 11. Критерии приёмки

Из папки `app/`:

1. `npm test` проходит целиком, включая новые `google.test.ts` и `calendar-api.test.ts`.
2. `npm run dev`, открыть `/settings`. Нажать «Подключить Google Календарь». Ожидание: браузер уходит на Google, после согласия возвращается на `/settings#integrations`, статус «подключён», видна почта.
3. Открыть `/calendar`. Ожидание: список встреч на 7 дней вперёд. Событие без ссылки на звонок отсутствует. Событие с повтором показано отдельными датами.
4. На событии Zoom нажать «Отправить бота». Ожидание: переход на `/meetings/:id`, статус `queued`, при живом воркере далее `joining`.
5. Открыть `/calendar` снова. Ожидание: у той же строки теперь «Открыть» и статус встречи.
6. На событии Google Meet кнопка неактивна с подсказкой.
7. В Настройках нажать «Отключить». Ожидание: статус «не подключён», `/calendar` вернул баннер.
8. Убрать `GOOGLE_CLIENT_ID` из `.env`, перезапустить, нажать «Подключить». Ожидание: сообщение «Google OAuth не настроен», приложение не падает.

## 12. Глоссарий

- **OAuth** — способ дать приложению доступ к вашему аккаунту в другом сервисе, не отдавая пароль.
- **Scope (разрешение)** — что именно приложению позволено делать с аккаунтом. Здесь только чтение событий календаря.
- **Access-токен** — короткий пропуск к данным, живёт около часа.
- **Refresh-токен** — долгий пропуск, по которому приложение само получает новый access-токен.
- **Redirect URI (адрес возврата)** — куда Google отправит браузер после согласия. Должен совпадать с записанным в Google Cloud Console символ в символ.
- **Testing mode** — режим приложения в Google Cloud Console до проверки Google. Работает только для добавленных Test users, refresh-токен живёт 7 дней.
